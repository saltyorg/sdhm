## Findings and Resolutions

### Standards

1. **Zero-value tracker safety:** `Tracker.Fail` could call a nil clock and write a nil map. A failing regression test now constructs `var tracker Tracker`, records more than the default history bound, and exercises recovery/readiness. The tracker lazily initializes its private map, clock, and bound while locked.
2. **Discarded health write error:** the handler now checks `json.Encoder.Encode`; after headers are committed, it returns because no safe fallback response remains.
3. **Test context:** the server cancellation test now derives its probe from `t.Context()` rather than `context.Background()`.
4. **Four-string store constructor:** retained. It is a possible data-clump smell, but it is the plan-approved deep-store boundary, has one production wiring path, and is protected against argument drift by wiring tests. Introducing another public configuration type would add scope without changing behavior.

All rewrite commit subjects satisfy the workspace Conventional Commit policy. No package-boundary, logging, concurrency-ownership, workflow-permission, or other documented-standard violation was found.

### Specification

1. **Composite VM qualification:** the spec still required one final all-in-one core run, while the user explicitly selected `minimal` after core proved unsuitable. The contract now states the evidence honestly: initial real-Saltbox naming/events, complete static Saltbox consumer/history validation, and later reviewed minimal-profile synthetic-network lifecycle, outage, recovery, filesystem, crash-loop, and readiness runs. It does not claim an uninterrupted final-head real-network run.
2. **Terminal event error priority:** simultaneous source message closure and a buffered source error could lose the exact diagnostic in the abstract adapter contract. A failing repeated test reproduced the loss. The mapper now checks queued source errors before messages and once more on message closure; the daemon's mapped-channel priority remains intact. Pinned Moby v0.2.1 already sends the error and never closes `Messages`, so this hardens the documented contract without changing normal production flow.
3. **Stale tracking metadata:** the design no longer says written review is pending. The implementation plan now identifies its unchecked boxes as preserved prospective instructions and points to the evidence ledger as the completion record.
4. **Compatibility inventory:** the design now explicitly lists literal health addresses, valid port range, GET-only health routing, and special-file rejection among intentional changes already authorized by its detailed sections and observed in A/B comparison.
5. **Health server wording:** the lifecycle contract now distinguishes `Shutdown`'s context-bounded wait from the daemon's unconditional `Done` join, matching the implementation.

No unauthorized production scope was found.
