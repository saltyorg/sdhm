# SDHM Go 1.27 Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace SDHM with a Go 1.27 daemon whose Docker snapshots are authoritative, hosts-file writes are transactional and recoverable, scheduling is owned by one event loop, and every external behavior is tested.

**Architecture:** A small `daemon` core owns orchestration interfaces and one event loop. Concrete `docker`, `hosts`, and `health` adapters remain deep modules, while `command` parses and validates Cobra input and `cmd/sdhm` performs production wiring.

**Tech Stack:** Go 1.27.0, Cobra 1.10, Moby client/API 1.52, standard `testing`, `testing/synctest`, `log/slog`, `net/http`, GitHub Actions, Make.

**Spec:** `docs/superpowers/specs/2026-09-01-sdhm-go-1.27-rewrite-design.md`

## Global Constraints

- Use Go 1.27.0 and do not add compatibility code for older Go versions.
- Preserve the existing comma-separated `--networks/-n` contract and default it to `saltbox`.
- Add optional `--default-network`; when omitted choose `saltbox` if monitored, otherwise the first configured network.
- Emit bare plus qualified aliases on the resolved default network and qualified aliases only on every other network.
- Never call the hosts store after an incomplete Docker snapshot.
- Never use a cross-filesystem copy fallback for a hosts-file replacement.
- Preserve byte-for-byte everything outside the managed body, including both
  marker lines and the END suffix; never normalize user-owned EOF whitespace.
- Use `log/slog`; do not create a replacement logging wrapper.
- Define interfaces where `daemon` consumes them; keep filesystem fault injection private to `hosts`.
- Use `testing/synctest` or channels for time-sensitive tests; do not add timing sleeps to unit tests.
- Use Makefile targets for repository builds and tests.
- Use `apply_patch` for file edits and deletions.
- Do not stage or commit without explicit user authorization. Each task records only a suggested Conventional Commit subject.
- Preserve unrelated user files and ignored workspace state.
